# Quest port Auto-Cloud bridge

Monster Train 2 (2742830) is registered alongside StS2. Shared UID and matching signing are required.
`PortAutoCloud.java` is shared with the port APK. Rebuild ports with the updated shared source to use the lifecycle lock. The port invokes it before Unity starts. The service invokes it after registered process death, before releasing the Steam app session.

Steam itself downloads/uploads Auto-Cloud through its existing logged-in session. The bridge maps root 12 (WinAppDataLocalLow) to the Quest external files directory, using the Proton-prefix save tree Steam actually downloads. Every cloud file used for reconciliation must match its SHA1 in `remotecache.vdf`. The inventory and file contents are rechecked before mutation. The bridge never reads login files or handles credentials. `tools/cloud_inventory.c` remains a read-only RemoteStorage diagnostic. Its enumeration provides no authority to delete Auto-Cloud files.

Default mode is download-only, with reports under runtime `files/autocloud/2742830-before-start.json` and `2742830-after-exit.json`. Losing bytes are retained on Quest as `.conflict-<epoch-seconds>-<hash-prefix>` before replacement. `preferences-local.json` is local-only according to the actual Steam rules.

After reviewing the first report, create runtime `files/autocloud/2742830.allow-uploads` to permit staging at process exit. The marker is checked again at the mutation boundary. Startup reconciliation always uses download-only mode. The Steam client performs network synchronization on app-session exit. Confirm completion using `cloud_log.txt` and refreshed cache hashes.

MT2's saved local examples and `SaveDataJson`/`EditorManagedSaveData` serialization use JSON objects. This includes metagame backups, preferences, active saves, and run history. Reconciliation rejects empty files, malformed UTF-8, truncated JSON, trailing data, and lenient JSON syntax. It compares bytes, size, and mtime across a 250 ms stability check and checks the snapshot again before mutation. Uploads use the validated snapshot bytes.

Runtime `files/autocloud/2742830-state.json` stores per-file local and cloud hashes, the cloud ChangeNumber and timestamp, and the account owning that history. Writes use temporary files, fsync, and replacement. Existing local files are recorded before reconciliation, including files whose JSON validation fails. An absent file with a reconciled baseline remains locally deleted across restarts while the cloud SHA1 and ChangeNumber match that baseline. If either differs, the validated cloud copy is downloaded, subject to the future-timestamp guard. This uses revision changes even when the cloud mtime is equal or older. ChangeNumber is inventory-wide, so a change elsewhere in that inventory can also permit a download. Seen-local-only history from an interrupted or invalid reconciliation remains protected until a cloud baseline is established. An absent file with no history can receive a new cloud download. A change of cloud account blocks reconciliation pending explicit history review.

When both sides have a common baseline, hashes determine which side changed. Concurrent changes retain both copies and block replacement. A one-sided change follows the content baseline even when mtimes disagree. Without a baseline, time-based selection requires a gap greater than 120 seconds and no greater than 24 hours. Divergent saves with any future timestamp are retained for review. Near-equal timestamps and excessive skew produce a conflict report and preserve the cloud copy alongside the local save.

The bridge never deletes a cloud mirror file or stages cloud deletion, including when uploads are enabled. A crash between the game's delete and rename must leave every cloud save intact, including metagame progression, backups, preferences, and run history. Quest run-end deletions are not propagated. PC keeps its cloud copy. Local deletion protection leaves the last reconciled revision in history so a later changed cloud SHA1 or ChangeNumber can be downloaded.

The existing MT2 decompilation establishes how a saved finished run is treated on the PC game path. `D:/Claude/mt2_work/decomp/SaveData.cs` defines `GameSequence.GameOver`. `SaveManager.cs` lines 3601-3604 make `IsAlive()` false for that sequence, and lines 3620-3627 exclude it from active gameplay. `GameStateManager.cs` lines 726-737 route a loaded finished run to the Game Over screen, attach `FinishRun`, and call `FinishGameOver` when that screen completes. `EndGame` sets the GameOver sequence at line 485. These are static code observations. A retained cloud copy that predates completion can still contain an active sequence. Recognition of that older active snapshot as already completed through run history was not established.

Before-start reconciliation and the complete after-exit reconciliation/session-release pass share `files/autocloud/2742830.lock`, using a JVM monitor and an OS file lock across the runtime and port APKs. The service checks `port-processes` registrations using the registered PID and Linux start time, direct `/proc/<pid>` existence, and ActivityManager observations for the shared UID. ActivityManager package/process names also cover startup before registration. A changed start time identifies PID reuse. The service never enumerates `/proc`. Positive liveness suppresses the pass, and a second check suppresses release if a relaunch appeared during reconciliation. Missing PID evidence or an unreadable registration directory gets a 15-second grace period measured with `SystemClock.elapsedRealtime()`. The service logs entry into uncertainty and logs once when the timeout treats that identity as not alive. Positive evidence resets its timer. Registration and AppID identities have independent timers.

QA round 2 finding 2 correctly identified that `if (processes == null) return true` could block after-exit work forever. Its blanket assertion that Android 12L necessarily returns null for this app is rejected. AOSP Android 12 permits `domain proc:dir r_dir_perms`, while init mounts procfs with `hidepid=2,gid=readproc`. Hiding other UIDs does not by itself deny listing the directory. This runtime and the signed port share `com.steamruntime.shared`, so same-UID visibility is relevant. Quest-specific policy and the actual result remain unverified because this round uses no device access. Both null and filtered listings are bypassed by the new registered-PID path. [AOSP directory policy](https://android.googlesource.com/platform/system/sepolicy/+/refs/heads/android12-release/public/domain.te), [AOSP procfs mount](https://android.googlesource.com/platform/system/core/+/refs/tags/android-12.0.0_r31/init/first_stage_init.cpp).

Logged-off state blocks changes. Missing, ambiguous, changing, or empty cloud inventories block reconciliation. Deleted or absent mirror entries are skipped individually, including deletion tombstones, and a bad file is reported without aborting unrelated files. Numeric `syncstate` values alone never authorize deletion. Empty RemoteStorage enumeration supplies no evidence that an Auto-Cloud account is empty.
